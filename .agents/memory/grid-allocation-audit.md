---
name: Grid allocation audit
description: Trading safety invariants found during the live Grid audit.
---

Ожидающие SELL-уровни сетки — это резервация GRINCH, поэтому их суммарное количество не может превышать свободный баланс после вычета открытой DCA-позиции. Нельзя считать весь wallet «сеточным» только потому, что старые SELL-уровни уже были созданы: при устаревшей аллокации runtime-guard может разрешить продажу DCA-токенов.

**Why:** При live-аудите 8 августа 2026 года waiting SELL-уровни суммарно превышали фактический баланс GRINCH более чем в два раза, а весь баланс одновременно принадлежал одной открытой DCA-позиции. Это создаёт риск oversubscription и продажи резерва DCA.

**How to apply:** При rebuild/recenter/near-density сохранять инвариант `waiting_sell_grinch <= wallet_grinch - dca_reserved_grinch`; перед каждым SELL проверять не только конкретный ордер, но и актуальную совокупную сеточную аллокацию.

При rebuild сам резерв Grid нужно заново сверять с физическим GRINCH после DCA, а не только брать максимум из старого JSON и старых SELL. Если старых уровней больше доступного резерва, сначала удаляются самые дальние stale SELL; остаток распределяется по новым слотам с нормировкой весов только для этих слотов.

**Why:** Пирамидальные веса нормированы для полного набора уровней. После удаления одного уровня применение первого веса к свободному остатку снова могло создать аллокацию выше физического резерва.

**How to apply:** После любого rebuild проверять сумму waiting Grid SELL и не позволять ей превышать `max(0, wallet_grinch - total_dca_reserved_grinch)` даже с учётом округления и минимального размера ордера.

Адаптивный `GridAI.get_sell_target_pct()` должен использоваться и при проверке прибыльности BUY→SELL, и при создании cycle SELL. Проверка только по полному `step_pct` может пропустить BUY, если фактический SQUEEZE/DOWNTREND target ниже шага и round-trip после двух комиссий и газа становится убыточным.

**Why:** В SQUEEZE target составляет около `0.85 × step`; при шаге 4% это ниже безубыточного порога для небольших BUY, хотя старый BUY-гейт проверяет полный 4%.

**How to apply:** Перед BUY вычислять прибыль по тому же target, который будет записан в cycle SELL, с учётом fee, buy gas и sell gas; не использовать отдельные расходящиеся формулы.
